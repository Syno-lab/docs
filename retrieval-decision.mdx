## 结论

- **主路径**：变更驱动 SoT + 字段 TTL。查询时读取带时间戳的 SoT 快照。
- **实时搜索**：只做白名单域名（VFS、使领馆、IRCC 等）内的兜底，不作为主入口。
- **arXiv**：仅在评测退化时触发检索，产出研究候选，不进入用户答案。
- **产品形态**：对外采用 Perplexity 式“答案 + 引用”，中间层采用 Mintlify 式封闭语料与变更触发更新，对内采用 SuperApp 式研究工作台。

## 背景

SynoAI 是面向升学、签证、移民的垂直领域助手。成功标准是答案可核验、可追溯，并能通过 L0/L2 门禁。

| 维度 | Perplexity | Mintlify | SuperApp AI | SynoAI |
| --- | --- | --- | --- | --- |
| 定位 | 通用答案引擎：搜索 + 引用 + 智能体 | 文档助手：只检索自有文档 | 多人协作 + Deep research | 领域 SoT + 门禁的垂直助手 |
| 语料 | 开放网络 | 自有文档，可信度一致 | 开放网络 + 团队资料 | 外部官方站点，可信度分级 |
| 更新方式 | 查询时实时搜索 | 站点重建时重建索引 | 查询时检索 | 官方源变更时更新 |
| 成功标准 | 广、快、可点开引用 | 答得准、有来源链接 | 协作与长研究 | 可核验、可追溯、可过门禁 |

## 三种方案的取舍

| 方案 | 借鉴 | 不借鉴 |
| --- | --- | --- |
| Perplexity | 答案 + 行内引用的交互、可追问 | 开放域实时搜索作为主路径 |
| Mintlify | 封闭语料；变更触发重建索引；工具调用检索；记录未答问题，用来发现语料缺口 | 默认语料可信度一致；没有字段级时效 |
| SuperApp AI | Deep research；多人协作审核 | 对外开放研究模式 |

Mintlify 能这样做，是因为它的语料由自己撰写，可信度一致，也不会被第三方悄悄修改。SynoAI 的语料来自外部官方站点，所以在 Mintlify 模式之上，还要补齐下一节的几层能力。

## 外部官方源的特殊问题

| 问题 | 应对 |
| --- | --- |
| 官方页面随时改版，不会通知 | 变更监控 + 字段 TTL，过期即标记“待核验” |
| 页面结构变化，导致抽取静默失败 | 抽取健康检查：必填字段缺失或格式异常时告警，并保留旧值，不用空值覆盖 |
| 官方来源之间互相矛盾（如使领馆与 VFS） | 用权威等级和字段归属仲裁，向用户展示冲突说明 |
| 页面被修改后，无法证明当时的内容 | 证据快照：保存原始页面与哈希，引用同时指向快照和原链接 |
| 抓取受限或失败 | 遵守站点抓取规则与频率限制；失败时保留旧值，标记“待核验” |
| 多语言版本不同步 | 建议以发布机关的原文版本为准，译文仅作辅助 |

## SynoAI 方案架构

| 层 | 做法 | 借鉴来源 |
| --- | --- | --- |
| 源注册表 | 每个白名单来源登记权威等级、负责字段、更新频率 | SynoAI 特有 |
| 采集与变更监控 | 定时抓取并 diff，同时做抽取健康检查；有变化才触发重新抽取 | Mintlify（变更触发） |
| 证据快照 | 每次变更都保存原始页面与哈希，供引用和审计 | SynoAI 特有 |
| SoT + 字段 TTL | 每个字段带 `last_verified_at` 与 TTL，过期标记“待核验” | SynoAI 特有 |
| 门禁 | 变更先过 L0/L2 门禁再写入 SoT；冲突和低置信度变更进入人工复核 | SuperApp AI（协作审核） |
| 查询路由与回答 | 政策类问题读 SoT 快照；过期或缺失时在白名单内实时补抓 | Mintlify（封闭检索）+ Perplexity（兜底实时搜索） |
| 质量闭环 | 未答问题驱动补源；评测退化触发 arXiv 研究检索 | Mintlify（未答信号） |
| 内部研究工作台 | Deep research，接入 arXiv 与 Semantic Scholar，产出只进候选库 | SuperApp AI |

## 回答规范

- 每个事实句都带引用：来源、字段、核验时间。
- 字段过期时显示“待核验”，并附官方原链接。
- 官方来源冲突时，标明以哪个来源为准，并说明原因。
- 语料没有覆盖的问题，如实告知并引导到官方渠道，不用开放网搜补答案。

## 考虑过的方案

### 开放域实时搜索（不采纳）

把 SynoAI 做成通用实时搜索产品会稀释垂直壁垒。开放域来源噪声大，时效叙事可能与官方政策冲突，容易污染 SoT。

### 查询时白名单实时搜索（不采纳为主路径）

每次查询都去白名单域名实时检索。可控性比开放域好，但延迟和成本高，答案难以复现，不利于 SLA。

### 变更驱动 SoT + 字段 TTL（采纳）

后台监控官方源的变更，更新 SoT；查询时读取快照，只在快照过期或缺失时于白名单内实时补抓。

## arXiv 的定位

- 不做常驻检索。nightly 演化发现评测指标退化时，再按问题检索 arXiv 与 Semantic Scholar。
- 产出“方案候选 + 离线评测结果”，进候选库前需过门禁。
- 不进入默认签证问答路由，也不直接当作 SoT。
- 复用现有的 `syno_scihub_harvester` 与 `essay_router` 的 arxiv 源，只把触发条件改为问题驱动。

## 源注册表最小字段

| 字段 | 说明 |
|---|---|
| `source_id` / `url` | 唯一标识与页面地址 |
| `jurisdiction` / `visa_type` | 适用国家与签证类别 |
| `authority_tier` | T0 政府官方、T1 授权代办（如 VFS）、T2 社区或经验来源 |
| `owned_fields` | 该来源权威负责的字段，如费用、材料、预约、处理时长 |
| `refresh_cadence` | 抓取频率 |
| `default_ttl` | 字段默认有效期，供字段 TTL 阶段直接使用 |
| `extractor` | 抽取方式或规则版本，便于追溯 |
| `required_fields` | 抽取健康检查的必填字段，缺失即告警 |

## 落地顺序

<Steps>
  <Step title="源注册表">
    先选一条线路（一个国家的一类签证）建立注册表，跑通后再扩展到 VFS、使领馆、IRCC 全量。
  </Step>
  <Step title="字段 TTL">
    使用注册表中的 `default_ttl`，为每个字段记录 `last_verified_at`。
  </Step>
  <Step title="变更监控">
    定时抓取与 diff，同时做抽取健康检查并保存证据快照；变更触发重新抽取与门禁。
  </Step>
  <Step title="查询路由">
    按意图路由到 SoT 快照，过期或缺失时白名单兜底；按回答规范输出引用，并记录未答问题。
  </Step>
  <Step title="arXiv 评测驱动">
    评测退化时触发研究检索，结果仅进入候选库，在内部研究工作台中复核。
  </Step>
</Steps>

## 不做的事

- 不把 SynoAI 做成第二个开放域实时搜索产品。
- 不让 arXiv 或其他研究来源直接进入用户答案或 SoT。
- 抽取失败时，不用空值或未过门禁的数据覆盖 SoT。
